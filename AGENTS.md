# image2PPT project

- The primary automatic mainline is the OpenCode runtime (`orchestrator=opencode`, `visual_review_backend=opencode`, `/api/v1/jobs`, `services/product/opencode_client.py`, and `skills/image2ppt-runtime/SKILL.md`), targeting maximally native-editable output (`text`, `shape` including `fill_gradient` and preset geometries, `chart`, `table`, and transparent/photo image modules) with bounded visual tolerance (`configs/fidelity_tolerance.json`). Hard safety gates (no duplicate overlaid text, no unknown-pixel bbox erasure, no source-ink ghosting, actual PowerPoint verification, and stateless `audit_delivery` scorecard/review receipts) remain mandatory.
- `POST /api/v1/jobs?orchestrator=editable_reconstruction` selects the direct MoMA runner. It uses uploaded images, in-process tools and the shared `skills/image2ppt-runtime/reconstruction-policy.md`. Check the recorded candidate state, actual PowerPoint edits, MoMA visual review and final audit. The r10/R12 pipeline route through `product.parallel_pipeline.run` remains the frozen comparison baseline (`parallel_review`; `parallel_auto` remains gated). Keep manually authored SlideIR and diagnostic decks separate from automatic results.

This repository contains a fixed PPTX compiler and the automatic screenshot-to-editable-PPT product. For automatic generation, development, debugging and acceptance, follow `skills/image2ppt-runtime/SKILL.md`, `services/product/OPENCODE_RUNTIME.md`, `skills/image2ppt/SKILL.md`, and `services/product/PARALLEL_R10.md`.

- On the OpenCode mainline, deterministic perception (local OCR, LayerD, PP-DocLayoutV3, optional SAM/RMBG-2.0) and optional VLM page-structure/OCR-proofreading (`parse_page_structure`) feed SceneGraph and the batch/regional reconstruction tools; `audit_delivery` runs `PageScorecard/1` and stateless visual audit before `finalize_job`. On the frozen r10 baseline, MoMA provides text/asset/surface planning and Go independently reviews. SceneGraph arbitrates ownership and relations; its adapter alone emits public SlideIR. Coding agents change and diagnose the product rather than performing production planning by hand.
- Preserve source wording, numbers, hierarchy, layout and proportions. Use local object/region replacement closures; font sharing must not propagate pixel failures across unrelated regions. Uncertain source pixels remain in safe raster backing. Never overlay duplicate text or erase unknown pixels by bbox. Treat these as implementation requirements, not declarations that the r10 baseline already satisfies them.
- Report visual integrity and editable completion separately. Missing independent reference denominators mean unknown recall. Record actual PowerPoint movement/deletion/save-reopen, target residual checks and the route's hash-bound visual review. Label WPS and human checks separately.
- Preserve originals, historical outputs, live services, stable asset bytes and unrelated worktree edits. Maintain durable model-call reservations, unknown-response handling and task-level generation commits. Do not store credentials in source or logs.
- The fixed compiler and public SlideIR remain unchanged unless explicitly required. Tables and charts are gated by `COMPILER.native_tables` / `COMPILER.native_charts` in `scripts/capabilities.mjs`; inspect `doctor` before relying on capabilities. `compose` packages already-authored IRs; it is not recognition. OCR/API planning belong to the product layer, not the fixed core.
- Run focused tests for changed product behavior and `./image2ppt.ps1 test` for protocol changes. Compiler/OOXML changes additionally require the synthetic demo, `scripts/check_demo.mjs`, actual-file previews and retained reports. Synthetic fixtures prove tool behavior only. Documentation-only changes require reference/sync/package validation, not customer-image model calls.
- In bash use `./image2ppt.sh <cmd>`; PowerShell uses `./image2ppt.ps1 <cmd>`. Preserve the PowerShell wrapper's UTF-8 BOM.
- Codex skill maintenance source is `skills/image2ppt/`; `.agents/skills/image2ppt/` is its generated installed copy. Use `python exports/sync_codex_skill.py` then `--check`, and re-export with `exports/build_source_package.py` plus `exports/package_skill_entries.py`. Exports do not install the skill. Keep its code and compilation capabilities; do not apply its manual pixel threshold as a universal automatic-product gate.
