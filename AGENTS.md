# image2PPT project

This worktree converts uploaded slide images, including AI-generated pages, into presentations people can edit in PowerPoint. Submit new automatic jobs through the OpenCode runtime at `POST /api/v1/jobs` using `services/product/opencode_client.py`. The host builds a deterministic baseline before the Agent sees the job. Use the [engineering skill](skills/image2ppt/SKILL.md) for development, the [runtime skill](skills/image2ppt-runtime/SKILL.md) for the production Agent and the [runtime guide](services/product/OPENCODE_RUNTIME.md) for deployment and delivery.

For each applicable object, verify the edit a user needs on a copy of the actual PPTX, then save, close and reopen it.

- Replace one business field or number independently. Keep decorative separators outside the field. Check the new wording, the original location and its neighbors. For ambiguous source glyphs keep the crop, candidate reading and confirmation status. Track editability and confirmed wording separately.
- Recolor a card while its label, icon or photo stays in place. When intended to move as one card, select it once and verify the accompanying parts move. Delete an independent photo and verify its title and the exposed background. Check transparent icons against a contrasting fill.
- Edit a cell or supported chart datum through its native PowerPoint object when the source provides the underlying information. A complex visual can fall back to a movable image of that one object. Whole-page raster fallback cannot qualify as an editable delivery.

Allow minor font, gradient and shadow differences within the configured visual tolerances (`configs/fidelity_tolerance.json`). Preserve content, hierarchy and proportions. Require clear ownership for erased pixels, clean old locations, actual PowerPoint checks and the independent review receipt bound to the checked composition.

Use the frozen r10/R12 pipeline (`product.parallel_pipeline.run`, `services/product/run_local.py`) for comparisons. Its [runbook](services/product/PARALLEL_R10.md) describes `parallel_review` and the gated `parallel_auto` mode. Label manual comparisons, compiler fixtures and evidence replays separately from fresh automatic uploads.

- On the OpenCode mainline, local OCR, LayerD and configured detectors supply evidence. The host controls reconstruction and pixel ownership. The Agent chooses repairs through its granted tools. A separately configured reviewer inspects the source, final render and edit evidence. Identify both models from the actual job receipts. SceneGraph arbitrates ownership and relations, and only its adapter emits public SlideIR.
- Preserve source wording, numbers, hierarchy, layout and proportions. Use local object/region replacement closures; font sharing must not propagate pixel failures across unrelated regions. Uncertain source pixels remain in safe raster backing. Never overlay duplicate text or erase unknown pixels by bbox. Treat these as implementation requirements, not declarations that the r10 baseline already satisfies them.
- Report visual integrity, specified edits passed, actual PowerPoint checks, independent model review and human/WPS acceptance separately. Record missing independent reference denominators as UNKNOWN. For each retained file state whether it is an internal candidate, an available download or an automatically accepted delivery. Use the job's artifact list and selection receipt to identify the published file.
- Preserve originals, historical outputs, live services, stable asset bytes and unrelated worktree edits. Maintain durable model-call reservations, unknown-response handling and task-level generation commits. Do not store credentials in source or logs.
- The fixed compiler and public SlideIR remain unchanged unless explicitly required. Tables and charts are gated by `COMPILER.native_tables` / `COMPILER.native_charts` in `scripts/capabilities.mjs`; inspect `doctor` before relying on capabilities. `compose` packages already-authored IRs; it is not recognition. OCR/API planning belong to the product layer, not the fixed core.
- Run focused tests for changed product behavior and `./image2ppt.ps1 test` for protocol changes. Compiler/OOXML changes additionally require the synthetic demo, `scripts/check_demo.mjs`, actual-file previews and retained reports. Synthetic fixtures prove tool behavior only. Documentation-only changes require reference/sync/package validation, not customer-image model calls.
- In bash use `./image2ppt.sh <cmd>`; PowerShell uses `./image2ppt.ps1 <cmd>`. Preserve the PowerShell wrapper's UTF-8 BOM.
- Codex skill maintenance source is `skills/image2ppt/`; `.agents/skills/image2ppt/` is its generated installed copy. Use `python exports/sync_codex_skill.py` then `--check`, and re-export with `exports/build_source_package.py` plus `exports/package_skill_entries.py`. Exports do not install the skill. Claude's independent source is `skills/image2ppt-claude/`; never overwrite it with or derive it from Codex wording.
- The old Codex hand-planning workflow is retained in `skills/image2ppt/references/legacy-manual-workflow.md` for explicitly requested historical comparisons and compiler fixtures. Keep its code and compilation capabilities; do not apply its manual pixel threshold as a universal automatic-product gate.
