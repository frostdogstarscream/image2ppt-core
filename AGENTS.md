# image2PPT project

This project implements a Codex-assisted screenshot-to-editable-PPT prototype.

- Two skill flavors ship from separate maintained sources: the Codex skill from `skills/image2ppt/` (installed at `.agents/skills/image2ppt/`) and the Claude Code skill from `skills/image2ppt-claude/` (installed at `~/.claude/skills/image2ppt/`). Edit the maintained source, then re-export with `exports/build_source_package.py` + `exports/package_skill_entries.py`. Never copy one flavor over the other, and never regenerate the Claude flavor by string-replacing the Codex one — that drifts silently.
- Treat the source page as the design reference. Preserve its wording, numbers, layout and proportions. Do not apply generic presentation redesign defaults to restoration.
- Use the bundled Artifact Tool runtime and fixed compiler. The model step runs in the current Codex conversation; project scripts do not call a model API.
- Preserve originals and all completed output versions. Synthetic fixtures establish only tool-chain behavior, not real-image accuracy or human acceptance.
- Run `./image2ppt.ps1 test` for protocol changes. For compiler or OOXML adapter changes, run the synthetic demo and `scripts/check_demo.mjs` on its IR, inspect actual-file previews, and retain verification reports. In Claude Code the shell is bash: invoke `./image2ppt.sh <cmd>`, which forwards to `image2ppt.ps1`; `./image2ppt.ps1` is a bash syntax error. Non-ASCII in `image2ppt.ps1` also requires the file to keep its UTF-8 BOM, or Windows PowerShell 5.1 fails to parse it.
- Native tables are supported: `COMPILER.native_tables` in `scripts/capabilities.mjs` is the switch, `scripts/ir.mjs` derives the `table` node type from it, and `compile.mjs`/`compose.mjs` declare the owning slides to the finalizer. Native charts are supported the same way, gated by COMPILER.native_charts; they declare materializeLiteralChartWorkbooks so the finalizer snapshots the literal data into an honest embedded workbook. PDF, OCR, inpainting and automatic batch recognition remain outside v0.1. `compose` assembles already-authored page IRs into one deck, page by page; that is packaging, not recognition. Extend beyond this only when requested and with representative source evidence.

## Cursor Cloud specific instructions

- Core and vision use separate virtualenvs because they pin different Pydantic and Pillow versions. Core is `.venv` (`requirements-core.lock`, then `pip install --no-deps -e .`). Vision is `services/vision/.venv` (the package plus `pytest==8.3.4`, `httpx==0.28.1`, and `jsonschema==4.23.0`). Do not install `services/vision/requirements-linux.lock` on a CPU VM; that freeze includes Torch and NVIDIA CUDA wheels.
- Login shells load `/etc/profile.d/image2ppt.sh`, which sets `USERPROFILE`, `IMAGE2PPT_NODE` (`/usr/local/bin/node`), `IMAGE2PPT_PYTHON` (`.venv/bin/python`), and `IMAGE2PPT_PROJECT_ROOT`. `image2ppt.ps1` calls `Join-Path` on `USERPROFILE` before it reads `IMAGE2PPT_NODE`; an empty `USERPROFILE` fails the script. PowerShell 7 provides `./image2ppt.sh`.
- Protocol tests: `./image2ppt.sh test`. Core orchestration tests: `.venv/bin/python -m unittest discover -s tests -p 'test_*.py'`. Saved-page check that does not need the private renderer: `node scripts/main.mjs validate --input examples/synthetic/slideir.json`.
- `@oai/artifact-tool` is not on the public npm registry, and the Codex Presentations `container_tools` validators are not in this checkout. `python -m image2ppt doctor`, `compile`, `demo`, and `replay` stop until `node_modules` and `presentations_skill` are supplied (environment variables or `runtime.local.json`). Install writes `runtime.local.json` with only the core Python path.
- Vision CLI: `services/vision/.venv/bin/image2ppt-vision doctor`. `serve` needs `VISION_TOKEN` and is not started on boot. OCR stays off without a local model manifest; segmentation also needs CUDA and torch. Three vision tests import scripts that are not in this tree (`merge_native_batches.py`, `services/vision/tools/upgrade.py`, `freeze_visual_baseline.py`). API-evaluation tests that freeze a compiler runtime need `@oai/artifact-tool`.
