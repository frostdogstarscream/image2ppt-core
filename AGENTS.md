# image2PPT project

- The explicit `orchestrator=opencode`, `visual_review_backend=opencode` path uses the autonomous runtime Skill at `skills/image2ppt-runtime/SKILL.md`. It may compose basic MCP tools or choose the existing pipeline shortcut. The runtime Agent proposes evidence and scenes; the existing private adapter emits public SlideIR. Actual Office and source-pixel safety gates remain required. OpenCode performs visual self-review on this path without Go. The existing pipeline keeps its current default reviewer.

This repository contains a fixed PPTX compiler and the r10 automatic screenshot-to-editable-PPT product. For automatic generation, development, debugging and acceptance, follow `skills/image2ppt/SKILL.md` and the active product worktree's `services/product/PARALLEL_R10.md`.

- The automatic entrypoint is `product.parallel_pipeline.run`, used by the upload service and `services/product/run_local.py`. Default mode is `parallel_review`; `parallel_auto` remains gated. If this checkout lacks the product entrypoint, locate the established product worktree. Do not replace it with legacy serial planning, a hand-authored SlideIR, or a manually assembled deck and report automatic success.
- MoMA provides text, asset and surface evidence/planning; Go independently reviews. Local OCR, shared LayerD and optional SAM supply evidence/candidates. SceneGraph arbitrates ownership and relations; its adapter alone emits public SlideIR. Codex changes and diagnoses the product rather than performing its production planning by hand.
- Preserve source wording, numbers, hierarchy, layout and proportions. Use local object/region replacement closures; font sharing must not propagate pixel failures across unrelated regions. Uncertain source pixels remain in safe raster backing. Never overlay duplicate text or erase unknown pixels by bbox. Treat these as implementation requirements, not declarations that the r10 baseline already satisfies them.
- Report visual integrity and editable completion separately. A source-backed page or one editable date is not a fully reconstructed page. Missing independent reference denominators mean unknown recall. Actual PowerPoint movement/deletion/save-reopen, target residual checks and hash-bound Go review are distinct gates; automated PASS is not human or WPS acceptance.
- Preserve originals, historical outputs, live services, stable asset bytes and unrelated worktree edits. Maintain durable model-call reservations, unknown-response handling and task-level generation commits. Do not store credentials in source or logs.
- The fixed compiler and public SlideIR remain unchanged unless explicitly required. Tables and charts are gated by `COMPILER.native_tables` / `COMPILER.native_charts` in `scripts/capabilities.mjs`; inspect `doctor` before relying on capabilities. `compose` packages already-authored IRs; it is not recognition. OCR/API planning belong to the product layer, not the fixed core.
- Run focused tests for changed product behavior and `./image2ppt.ps1 test` for protocol changes. Compiler/OOXML changes additionally require the synthetic demo, `scripts/check_demo.mjs`, actual-file previews and retained reports. Synthetic fixtures prove tool behavior only. Documentation-only changes require reference/sync/package validation, not customer-image model calls.
- In bash use `./image2ppt.sh <cmd>`; PowerShell uses `./image2ppt.ps1 <cmd>`. Preserve the PowerShell wrapper's UTF-8 BOM.
