# image2PPT project

This project implements a Codex-assisted screenshot-to-editable-PPT prototype.

- Two skill flavors ship from separate maintained sources: the Codex skill from `skills/image2ppt/` (installed at `.agents/skills/image2ppt/`) and the Claude Code skill from `skills/image2ppt-claude/` (installed at `~/.claude/skills/image2ppt/`). Edit the maintained source, then re-export with `exports/build_source_package.py` + `exports/package_skill_entries.py`. Never copy one flavor over the other, and never regenerate the Claude flavor by string-replacing the Codex one — that drifts silently.
- Treat the source page as the design reference. Preserve its wording, numbers, layout and proportions. Do not apply generic presentation redesign defaults to restoration.
- Use the bundled Artifact Tool runtime and fixed compiler. The default skill/manual workflow keeps model authoring in the current conversation. The separately authorized `scripts/auto_workflow.py` validation workflow explicitly calls server-hosted model APIs; it must retain source/response/build bindings, bounded calls and machine-versus-human acceptance boundaries. Importing modules or running the original commands must not trigger model calls.
- Preserve originals and all completed output versions. Synthetic fixtures establish only tool-chain behavior, not real-image accuracy or human acceptance.
- Run `./image2ppt.ps1 test` for protocol changes. For compiler or OOXML adapter changes, run the synthetic demo and `scripts/check_demo.mjs` on its IR, inspect actual-file previews, and retain verification reports. In Claude Code the shell is bash: invoke `./image2ppt.sh <cmd>`, which forwards to `image2ppt.ps1`; `./image2ppt.ps1` is a bash syntax error. Non-ASCII in `image2ppt.ps1` also requires the file to keep its UTF-8 BOM, or Windows PowerShell 5.1 fails to parse it.
- Native tables are supported: `COMPILER.native_tables` in `scripts/capabilities.mjs` is the switch, `scripts/ir.mjs` derives the `table` node type from it, and `compile.mjs`/`compose.mjs` declare the owning slides to the finalizer. Native charts are supported the same way, gated by COMPILER.native_charts; they declare materializeLiteralChartWorkbooks so the finalizer snapshots the literal data into an honest embedded workbook. PDF, OCR, inpainting and automatic batch recognition remain outside v0.1 for the conversation-authored workflow. `compose` assembles already-authored page IRs into one deck, page by page; that is packaging, not recognition. Extend beyond this only when requested and with representative source evidence.
- The layered v3 pipeline (`services/vision/src/image2ppt_vision/layered/`, entry `scripts/layered.py` / `./image2ppt.ps1 layered`) is the one exception: it runs OCR, SAM2 and LaMa on the dev GPU worker (`deploy/layered-worker/compose.yaml`, never the production containers) and inpaints source text out of cutout pixels. The slide fill is a solid colour, with text, shapes and cutouts as separate objects above it. Only `capabilities({pipeline:'layered'})` reports `automatic_ocr`/`automatic_inpainting`. A page is FAILED if re-OCR finds text left on the background or any OCR line is unowned; otherwise REVIEW_REQUIRED at best. Verify a job with `scripts/check_automatic_delivery.py --job <job>` (v3 mode by `LayeredJob/1`). The optional DeepSeek call only regroups lines into paragraphs and is hash-bound; tokens and keys stay on the server.
