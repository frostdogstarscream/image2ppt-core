# 截图转可编辑 PPT 的效果优先实验计划

基线为 `feat/region-crop-fallback` 的 `056a356`。原始截图是画面参考，已认可的半自动细化 PPTX 是编辑行为参考。目标是只上传图片即可自动完成重建。

## 模型与职责

OpenCode 自动化入口默认使用 OpenCode Go 正式模型 `hy4`。Agent 看整页与局部，提出对象归属、字段边界和编辑动作。OCR 提供文字和位置，LayerD 提供前后层证据，SAM、RMBG 和背景拟合生成可比较的候选。SceneGraph 记录最终归属。实际 PowerPoint 回渲染决定候选能否通过。每次实验记录代码提交、输入哈希、模型实际 ID、模型调用与工具成本、各阶段耗时、PPTX 哈希。

## 实施顺序

| 阶段 | 改动位置和设计 | 通过条件 |
|---|---|---|
| A 建立基线 | 在同一组图片上记录原配置及只切换 Hy4 的两组结果。固定 OCR、LayerD 输入、模型预算及 Office 环境，记录未启用或失败的模型。 | 两个模型条件各有独立运行记录。图像、工具调用、产物下载、PowerPoint 打开均有证据。模型无法执行则单列失败。 |
| B 先修文字，再做截图兜底 | 在 `runtime/batch_backbone.py` 区域失败分类之前标注“应可编辑”“素材内在文字”“待判断”。保护可修文字免受扩框或合并吞入。将最终裁图提交移至局部修复后；同步收窄 `parallel_pipeline.py` 的 r10 种子。右上角位置仅作为 Logo 线索。 | 即使截图覆盖某个 KPI 超过 80%，该 KPI 仍能独立恢复；品牌字不重复。比较高价值字段漏项、误擦和内容错误。 |
| C 分清能力和分母 | 改 `scorecard.py` 与 `runtime/service.py`，分别记录原生编辑、经验证可移动图片、原位重复图片、底图保留。默认交付排除重复图，实验模式可保留。以人工标注的应编辑行计算非 Logo 文本召回，缺分母时报未知。 | 同版稿插入重复截图不能提高原生编辑率。计分和交付清单与实际 PPTX 对象对应；同一区域不重复计分。 |
| D 先建父框，区分两种删除态 | 使容器恢复能独立于前景成功数运行并支持局部重试。对 `region_crop.py` 按遮挡次序建立背景：删除子图时露出卡片；删除父卡片时露出画布。把删除态参考图与底板写回目标分别记录。 | 移动图标、删除图标、删除父卡片三种编辑后均无重复图案或方补丁；相邻对象位置稳定。 |
| E 按对象比较候选 | 同一困难区域运行背景反混合、LayerD、SAM、RMBG 等适用候选，用原背景、对比底色和删除态回渲染选优。保留照片及软件截图的完整矩形。视觉 Agent 对行业名与项目名、指标值与说明分别提出编辑字段。 | 细边、阴影完整，图标可移动，照片保持语义完整；可单改项目名或数字，邻项、文字强调及卡片布局稳定。 |
| F 控制合并和重试 | 合并前检查面积、受保护字段和容器边界。保留单种子框供拆回，使用带来源的稳定种子身份隔离失败与恢复。区域失败进入任务摘要；记录 Layout 冷启动、缓存命中、模型推理分项耗时，再决定是否常驻。 | 相邻小框合并超限时仍可独立交付；第二次重试不会误伤无关对象；模型异常与正常无候选可以区分。 |

## 真实页对照与取舍

1. 第一页改“26 项”、移动客户经理角色框、删除研发工作台截图，分别看旧字、底框、相邻内容。
2. 第二页改长一个项目名、改一个表格字段、换行业卡片底色，检查断行、字色、行列对齐和图片边缘。
3. 用 p08 复测重复图片。绑定具体运行产物，记录各区域面积、失败原因和编辑证据。另留未参与调参的截图作盲测。
4. 每轮从同一基线只切换对应实验项。优先比较逐项编辑成功、文字和数字正确性、局部残影与整页回渲染。模型调用、GPU 时间和维护成本作为次级指标。保留每一组候选和上一版 PPTX 供回看。
