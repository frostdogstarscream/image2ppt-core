# M1.1 校验与恢复可靠性修订

本轮基于 M1 评审处理 R01—R04，并补空清单、对象类型及精确错误断言。SlideIR 保持 0.1；保留 Artifact Tool，不接模型、不重新识别原图，不在本轮修复 F04 导出算法。

## 变更

| 项目 | 实现 |
|---|---|
| R01 实现指纹 | 以实际运行包 `__file__` 所在目录及已加载模块文件为依据，保存包路径、包版本、文件 SHA-256；分别生成 Python 核心、本地 JS/Python 工具链、渲染器身份、外部辅助工具指纹，再组合旧 `implementation_sha256` 字段供缓存使用 |
| R02 SQLite 故障隔离 | run.json 先保存；SQLite 错误及索引文件 I/O 错误记录到 stderr 和运行目录的 `index-warning.json`。忙/锁定最多尝试两次（每次 SQLite 等待 0.1 秒，间隔 0.05 秒）；损坏不自动删除。索引和诊断写入失败均不覆盖主任务异常 |
| R03 样式检查 | 逐字符分别比较 color/bold，任一已知属性不一致即 FAIL；未知属性独立记录到 `unknown_properties`，具体差异进入 `property_mismatches`；全部已知且一致才 PASS |
| R04 正式 IR 校验 | 在唯一 JS 验证器加入分层字段白名单和布尔类型检查；拒绝 `bold: "false"`、未知 `rotation`、空/null runs 等。保留原有 14 页使用的 description/source_text_bbox 元数据并检查类型/坐标 |
| 其他边界 | ProbeCases/RegressionSuite 最少一项；报告记录 executed_count；核对 IR 对象类型与实际 sp/pic/grpSp；重复 ID 测试断言中文业务诊断；显式未解析的主题色不能回落成低优先级 RGB |

指纹中的渲染器身份依据引擎名称、版本和包路径；外部辅助工具另有内容哈希。这不是整个专有运行时依赖树的供应链证明。工具链指纹保守覆盖 `scripts/` 下 `.mjs` 和 `.py`，因此无关工具脚本变化也可能触发重算。

`index-warning.json` 保存最后一次索引失败诊断，保留作为历史证据，不代表后续恢复必然仍有索引故障。SQLite 始终只是派生索引，不能替代文件哈希核验。新异常不会自动改写已有正式修订。

## 显式重建索引

```powershell
python -m image2ppt rebuild-index --directory '<直接包含 run-ID 的目录>' --output '<新的索引文件>.sqlite3'
# 未安装时可用：python scripts/core_cli.py rebuild-index ...
```

命令从该目录的 `run-*/run.json` 重建到一个**不存在的新文件**，旧索引即使损坏或被占用也保留。命令不自动替换正在使用的 index.sqlite3；如需切换，在相关运行停止后由操作者保留旧文件并切换。无运行记录、记录损坏或创建失败会报错，不能被宣称为成功重建。部分生成的新文件保留供诊断。

## 兼容边界

- 旧的合法保存结构继续使用 SlideIR 0.1。此前被忽略的未知语义字段会明确报错；需要先适配到支持的字段，或把来源说明放入独立文件。
- 原有 `description`（证据和素材）、`source_text_bbox`（文字源范围）继续兼容；它们不新增导出效果。
- 未知主题颜色保守返回未知，本轮没有实现完整主题解析器。
- 对象类型检查并不等于完整几何、素材转码或内容一致性验证。
- 新的实现指纹会使旧缓存失效；旧产物和历史 build.json 保留。
- F01—F04 的重建问题仍属于后续 M2；整体质量状态继续为 REVIEW_REQUIRED。

## 测试与证据

```powershell
./image2ppt.ps1 test
python -m unittest discover -s tests -p 'test_*.py' -v
```

原有 Python 测试文件仅收紧重复 ID 的断言；新增 `tests/test_m11.py` 包含 13 个边界测试。安装态测试复制实际核心包到独立目录、在新 Python 进程中加载并更改其行为，固定 JS doctor 返回值以隔离指纹测试，再验证 Runner 缓存失效。该测试不代表完整 Artifact Tool 渲染。SQLite 测试区分缺失（原测试）、真实损坏、真实排他锁及诊断写入失败；样式测试保留 PASS、FAIL、未知三类正常对照。

实际测试输出、保存 IR 兼容记录、合成导出、真实回归和本轮未改动文件的基线哈希保存在 `outputs/m1.1/`。最终统计见该目录的 `acceptance.json`。早期测试日志保留：其中一次测试 mock 复用了可变字典，另一次暂存目录重命名报 WinError 5；修正 mock 后的完整运行单独保存，不覆盖失败记录，也未据此宣称已解释或修复所有 Windows 文件系统故障。

工作区原有 `image2ppt.ps1`、`scripts/compile.mjs`、`scripts/pptx_xml.py` 的未提交改动，以及 slide/compose/compare 辅助文件均保留。实际导出验证使用该工作区编译链，测试结果不冒充纯净 77e53eb 编译环境的重测。PowerPoint/WPS 人工编辑和人工视觉验收仍未执行。
