# 分层 v3 流程验证记录（2026-10-27）

本记录对应分支 `codex/v3-layered`（基于 `558d20f`）。v3 是新增的独立流程，不替换 v2 自动流程，也不修改 v2 的记录和结论。

## 做法

每页拆成四层，最底层是清理过的背景：

1. **感知（服务器开发 GPU）**：OCR 识别文字行，逐字形测量墨迹、颜色和笔画；LaMa 把文字从页面上抹掉；SAM2 加对比度连通域找出形状与图元；可拟合为矩形、圆角矩形、椭圆且填充干净的区域做原生形状，其余做带透明度的 RGBA 抠图；再用 LaMa 修补图元下方的背景；最后对背景重新 OCR。
2. **排版（本地）**：用已安装字体对每行原图墨迹做栅格拟合，确定字号、字体候选、粗细和位置；拟合不了的行按本页实测比例回退。
3. **段落（本地，可选模型）**：确定性规则把行合成段落。启用模型时，每页只发一次纯文字请求（DeepSeek flash），模型只能重新分组和选对齐方式，不能改字；每个分组都要再过一遍几何兼容检查，不合格的回退到确定性结果。
4. **编译**：生成 SlideIR，由固定 Artifact Tool 编译器导出 PPTX，再从实际文件回渲染预览。

模型不看图片，不定位任何像素，也不生成文字。

## 完整性规则

- 对最终背景重新 OCR，若仍识别出文字（且不在刻意保留的抠图或背景证据内），该页 `FAILED`。
- 每条 OCR 行必须有唯一归属：原生文字、表格单元格、包含它的抠图、源像素保留块或背景。缺一条即 `FAILED`。
- 其余情况最好也只是 `REVIEW_REQUIRED`，没有人工或 Office 验收。
- 模型请求、证据和响应分别记录 SHA256；`scripts/check_automatic_delivery.py --job <任务>` 识别 `LayeredJob/1` 后只读复核全部文件哈希、输入绑定、PPTX 哈希、实际文件中的原生文字数量、OCR 覆盖、背景残留和模型哈希链。篡改模型响应后复核会报错（已实测）。
- `capabilities({pipeline:'layered'})` 才把 `automatic_ocr`、`automatic_inpainting` 列为支持；默认清单（对话授权流程）不变。

## 已知问题

- 第 11 页一个橙色图标被 OCR 读成“11”（置信度 0.926），仍作为原生文字输出。短而低置信、字体拟合不上的行（如 “B”“?”“品”）会保留源像素，但这一例的置信度高于阈值。
- 斜体未识别：第 13 页（P12）副标题原图为斜体，输出为正体。
- 字体是已安装候选，逐行拟合，不是原字体。试过整页统一为多数字体，三页 SSIM 全部下降，已撤回。
- 宽度限制会在不少行上缩小字号，避免候选字体比原文宽而溢出；这一点保守，会让个别行偏小。
- 柱状图、环形图、地图等以 RGBA 抠图保留，未重建为原生图表；14 页均未识别出带线框的表格，P5 等页的无框列表以原生文字加抠图表示。
- 部分低置信的真实短词（如第 15 页地图上的“蚌埠市”）按保留规则以源像素呈现，可见但不可编辑，已在 IR 的 `review_notes` 中列出。
