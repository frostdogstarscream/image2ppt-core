# 最小 ModulePlan

模块层是源图结构的独立记录，不是 SlideIR 新版本，也不是 PPT 原生分组。当前实现保留全部对象和既有 IR，仅增加边界、归属、包含关系和对齐证据，尚不自动移动对象。

## 契约与职责

- `ModuleProposal/2`：模型提出 1—12 个粗粒度模块，使用 `bounds_px.left/top/right/bottom` 明确原图像素边界，保留标签、角色、自报置信度、视觉依据及文字锚点。旧 `ModuleProposal/1` 的 `bbox=[x,y,w,h]` 仍可校验，但不得猜测其是否本想表达右下坐标。
- `ModulePlan/1`：程序验证提案后，生成模块成员、全部节点的归属状态、包含诊断、模块重叠、锚点冲突、对齐检查及独立的原图边缘观察。
- `SlideIR 0.1`：保持原始字节不变；语义模块记录保存在 sidecar 中。`authoring.json` 绑定模块计划哈希与原始模型响应哈希。

模型请求只携带已获授权的原图、固定文字及 bbox。205 个本地节点中的非文本图形、图片及层级元数据不外发，成员归属在本地计算。

## 校验原则

1. 源图、IR、请求和响应分别绑定；模块 ID 唯一，坐标有限且位于原图内，锚点必须存在。
2. 拒绝覆盖 80% 以上页面面积的单个兜底模块，防止失去模块区分。
3. 文本优先用 `source_text_bbox` 判断归属，其他对象用已有 IR 边界；这不证明后者在源图中已准确。
4. 只有一个模块覆盖参考框至少 98% 时才归属。多个模块同时包含则标记 ambiguous；未达到阈值则标记 unassigned。所有状态都保留对象，绝不删除或强制归到最近模块。
5. 另核对当前对象框是否越过模块超过 2 源像素。模块边界本身是候选，因此不能据此直接判定对象应移动。
6. 对齐检查区分提案坐标的一致性、原图边缘支持和实际应用。边缘支持使用 RGB 梯度、±3 像素搜索和 35% 线段支持率，属于启发式证据，不是边界真值。
7. 原图边缘分析可独立记录同侧边界差不超过 2 像素的关系，明确标记本地推导来源，不伪装成模型输出。
8. 本阶段所有关系均 `applied:false`。任何后续布局变更须生成新 IR、实际 PPTX 和前后验证。

## 使用

```powershell
python -X utf8 scripts/module_plan.py prepare --ir <现有页面/slideir.json> --output <新job目录> --model <模型ID> --base-url <已授权接口>
# 经授权后通过 run_supervised_jobs_secure.py 隐藏输入凭据并执行 job。
python -X utf8 scripts/module_plan.py apply --job <job目录> --output <新页面目录>
# 使用 compose_text_ledger.mjs 及固定编译器导出新页面。
python -X utf8 scripts/module_plan.py verify --folder <新页面目录> --pptx <实际PPTX>
```

`verify` 重新从原提案、IR 和源图计算模块计划，检查哈希、节点覆盖、文字台账及实际字体参数。`PASS_STRUCTURAL_ONLY` 不表示语义分类、边界精度、布局质量或人工验收通过。

第 05 页实测：7 个模块，186 个节点归属明确，19 个待核对；2 个包含问题、2 个锚点问题；模型的 3 条对齐关系均未通过证据检查，本地原图边缘观察支持 1 条顶部对齐关系。输出 IR 字节不变，新旧实际回渲染一致。
