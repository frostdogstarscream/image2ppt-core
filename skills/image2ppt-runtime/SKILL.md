# Host-precomputed Image2PPT workflow

1. **Read the host baseline.** Start with `get_job_context` for the frozen baseline, checked objects and available tools. Use `issue_blocks` to select work for planning and local reconstruction. Use `reading_blocks` to locate numbered text anywhere on the page. Each reading block identifies its `block`, numbered `image` and `inventory` of up to 30 marks. Fetch the relevant image, inventory and original by evidence ID with `get_evidence` (up to eight IDs per call). Use `prepare_page_evidence(page)` for a new measurement when it would resolve a specific doubt.
2. **Plan the user's edit.** Compare the original and the numbered region. Give each selected mark its intended route (`text`, `surface`, `asset`, `table`, `chart` or `preserve`) and role. Keep the partners that should travel with a card in `move_with`. Open a reported group conflict to identify a missing member or an unrelated neighbor. The host checks the surface outline and ink ownership. A surface can carry a `roundRect`, `homePlate` or `chevron` hint. Select high-confidence mistakes, split fields and newly numbered source text for `review_numbered_text` by object ID. Record the actual reading or skip reason, and keep ambiguous numbers and units for confirmation.
3. **Rebuild the affected objects.** Send a question block or up to 30 issue object IDs to `batch_reconstruct_page`. Commit its validated candidate at the current scene version. Check failures, Office attempts, isolation history and which objects the commit improved. A second local attempt requires changed findings, source evidence or strategy for that specific object. Each object has at most two attempts. Use the repair-history evidence to see skipped objects. Independent visual findings carry page and source bindings. Use the linked marks, and inspect unresolved or ambiguous locations before choosing a target. For local charts, the host verifies the categories and numeric data in the original.
4. **Verify the saved edit.** Compile, validate in PowerPoint, fetch the required source, render and edit evidence, and inspect the independent audit. For each applicable object, use these success criteria:

   - A business field or number can be replaced on its own. Its value and unit survive save/reopen, decorative dividers stay in place, and clearing the field reveals a clean background.
   - A card can change fill beneath its label and icon. A single selection moves the parts intended to travel together. Describe movement partners with `move_with`. Use `group` only as a role. An independent photo can be deleted while its title and neighboring objects survive. Inspect transparent asset edges on a contrasting background when that evidence is available.
   - A table field can be edited in its native cell. A chart with source-supported data can be changed using its native data. An independently movable complex visual may be retained as a single picture, including integral screenshot lettering. The page itself cannot be used as the fallback object.

Leave uncertain source pixels in the backing and record affected business fields as incomplete. Keep decorative separators and intrinsic logo lettering distinct from editable business fields.

Record each observed edit and any evidence still missing. A generic move/delete receipt measures the objects that were created. A user action such as single-selection card movement requires evidence for that action. Submit `record_visual_review` for content, completeness, layout, residual, background and editing, then inspect the outcome of `finalize_job`. Report the checked PPTX, the independent review provider and verdict, and the actual artifact selection. Missing verified independent review leaves the job in `REVIEW_REQUIRED`. This state can mean a downloadable review copy or diagnostic files only. A strict upload with an ineligible candidate and baseline has no selected PPTX. Report human and WPS acceptance only when performed.
